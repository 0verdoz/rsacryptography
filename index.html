1 Key Generation

Pick two distinct primes p and q. Their product n = p × q is the modulus, public to everybody. Euler's totient φ(n) = (p−1)(q−1) counts the integers below n that are coprime to it — it stays secret, because knowing it is equivalent to knowing the private key.

n — modulus
—
n = p × q
φ(n) — totient (secret)
—
φ(n) = (p−1)(q−1)
—
e × d ≡ 1 (mod φ(n))
Extended Euclidean algorithm — computing d = e⁻¹ mod φ(n)

Stallings' tabular form of Extended Euclid(m, b) with m = φ(n), b = e. Each row keeps two triples (A1, A2, A3) and (B1, B2, B3) satisfying the invariant m·A1 + b·A2 = A3 and m·B1 + b·B2 = B3. We repeatedly divide, exactly like ordinary Euclid, until B3 = 1. At that moment m·B1 + e·B2 = 1, so reducing mod m gives e·B2 ≡ 1 (mod m) — that is, B2 is the inverse d. (If B3 reaches 0 instead, gcd ≠ 1 and no inverse exists.)

🔓 Public key PU

{ e, n }
Published freely. Used to encrypt: C = Me mod n

🔒 Private key PR

{ d, n }
Kept secret. Used to decrypt: M = Cd mod n

2 Encryption  C = Me mod n

The plaintext is a number M with 0 ≤ M < n. (Real messages are chopped into blocks small enough to satisfy this.) Anyone holding the public key can compute the ciphertext.

C — ciphertext
—
C = Me mod n
Square-and-multiply — walking through Me mod n

3 Decryption  M = Cd mod n

The holder of the private key raises the ciphertext to the power d. Because e·d ≡ 1 (mod φ(n)), Euler's theorem guarantees (Me)d ≡ M (mod n) — the original plaintext comes back exactly.

Recovered plaintext
—
M = Cd mod n

4 How long would it take to break?

Everything an attacker needs is hidden behind one problem: factoring n back into p and q. Recover those and φ(n) = (p−1)(q−1) falls out, and then d is just one more run of the extended Euclidean algorithm — the same one in Stage 1. So the security of the whole scheme is exactly the cost of factoring, and that cost is what the charts below plot as p and q grow.

The gap between the two charts is the whole point. A better algorithm does not shave a bit off the attack — at 2048 bits it collapses the work from about 10³⁰⁸ operations to about 10³², some 275 orders of magnitude. RSA is secure not because factoring is impossible, but because even the best method anyone has found is still hopelessly far from feasible at the sizes we actually deploy.
